# Производные датасеты (Derived Datasets: L1, bars_1s, bars_1m)

## 1. Назначение и обзор

Производные датасеты строятся из нормализованного потока событий биржи (`data/processed/<exchange>/<symbol>/events/.../<YYYY-MM-DD>.parquet`).

Они оптимизированы для быстрого анализа, бэктеста среднечастотных стратегий, расчета индикаторов и машинного обучения без необходимости воспроизводить полный L2-стакан:

| Тип датасета | Имя (`kind`) | Шаг интервала | Назначение |
|---|---|---|---|
| **L1** | `l1` | Тиковый (на каждое событие стакана) | Лучший bid/ask и объемы на вершине книги на каждое изменение лучших цен или объемов |
| **Бары 1с** | `bars_1s` | 1 секунда ($10^9\,\text{ns}$) | Секундные агрегаты сделок с микроструктурными метриками (VWAP, imbalance, as-of mid/spread) |
| **Бары 1м** | `bars_1m` | 1 минута ($60 \cdot 10^9\,\text{ns}$) | Минутные агрегаты сделок для классического технического анализа и фичей |

---

## 2. Схемы данных

### Схема `L1` (`L1_SCHEMA`)

Каждая строка генерируется строго при изменении вершины стакана (цены или объема лучшего bid или лучшего ask). Если сообщение обновляет глубокие уровни и не затрагивает вершину, строка не создается.

| Поле | Тип Arrow | Описание |
|---|---|---|
| `ts` | `timestamp[ns, tz=UTC]` | Метка времени биржевого события, изменившего вершину стакана |
| `bid_px` | `float64` | Лучшая цена покупки (best bid) |
| `bid_sz` | `float64` | Суммарный объем на лучшей цене покупки |
| `ask_px` | `float64` | Лучшая цена продажи (best ask) |
| `ask_sz` | `float64` | Суммарный объем на лучшей цене продажи |

---

### Схема Баров (`BAR_SCHEMA`)

Используется для `bars_1s` и `bars_1m`.

| Поле | Тип Arrow | Описание |
|---|---|---|
| `ts` | `timestamp[ns, tz=UTC]` | Начало временного интервала бара (выровнено по сетке шага интервала) |
| `open` | `float64` | Цена первой сделки в интервале |
| `high` | `float64` | Максимальная цена сделок в интервале |
| `low` | `float64` | Минимальная цена сделок в интервале |
| `close` | `float64` | Цена последней сделки в интервале |
| `volume` | `float64` | Суммарный объем всех сделок интервала ($\sum q_i$) |
| `vwap` | `float64` | Средневзвешенная цена объема ($\sum (p_i \cdot q_i) / \sum q_i$) |
| `buy_volume` | `float64` | Объем сделок с агрессором-покупателем (`side == BUY`) |
| `sell_volume` | `float64` | Объем сделок с агрессором-продавцом (`side == SELL`) |
| `imbalance` | `float64` | Нормализованный дисбаланс потока ордеров: $(\text{buy\_vol} - \text{sell\_vol}) / \text{volume} \in [-1.0, 1.0]$ |
| `trades` | `int32` | Количество сделок в интервале |
| `mid_close` | `float64` (nullable) | As-of mid-цена $(bid + ask) / 2$ на конец интервала бара. `null` до первого снапшота L1 |
| `spread_close` | `float64` (nullable) | As-of спред $ask - bid$ на конец интервала бара. `null` до первого снапшота L1 |

---

## 3. Раскладка каталогов на диске

Все производные датасеты хранятся в формате Apache Parquet с партиционированием по годам и месяцам:

```text
data/processed/<exchange>/<symbol>/
  ├── _derived_manifest.json          # Манифест идемпотентности и версий
  ├── l1/
  │   └── year=2024/
  │       └── month=01/
  │           ├── 2024-01-01.parquet
  │           └── 2024-01-02.parquet
  ├── bars_1s/
  │   └── year=2024/
  │       └── month=01/
  │           ├── 2024-01-01.parquet
  │           └── 2024-01-02.parquet
  └── bars_1m/
      └── year=2024/
          └── month=01/
              ├── 2024-01-01.parquet
              └── 2024-01-02.parquet
```

## 4. Ключевые допущения и правила построения

1. **Старт книги с первого снапшота дня:**
   Книга восстанавливается независимо внутри каждого дня. До первого снапшота (`BOOK_SNAPSHOT`) книга считается неполной. Поэтому строки L1 начинают генерироваться строго после применения первого снапшота. Если день начался с апдейтов (например, 2024-01-02), первые секунды/десятки секунд дня в L1 отсутствуют.
2. **Пустые интервалы баров не заполняются:**
   Бары строятся только для тех временных окон, в которых произошла хотя бы одна сделка. Пустые секунды или минуты без сделок отсутствуют в таблице.
3. **Границы временных окон:**
   Интервал бара полуоткрыт справа: $[\text{bar\_ts}, \text{bar\_ts} + \Delta t)$. Сделка с меткой ровно на границе $t = \text{bar\_ts} + \Delta t$ относится к следующему бару (`bucket = ts // interval_ns`).
4. **Связка с L1 (`as-of` срезы):**
   Поля `mid_close` и `spread_close` вычисляются через бинарный поиск (`np.searchsorted`) как состояние последней известной записи L1, имеющей метку $ts < \text{bar\_ts} + \Delta t$. Если в начале суток сделки произошли до появления первого снапшота L1, эти поля остаются `null`.
5. **Численная точность агрегатов:**
   Вместо разностей кумулятивных сумм дня расчет сумм ведется по границам групп через векторный `np.add.reduceat`. Это гарантирует отсутствие катастрофической потери точности на больших суточных объемах: `vwap` строго лежит в диапазоне $[\text{low}, \text{high}]$, а `imbalance` строго в $[-1.0, 1.0]$.

## 5. Идемпотентность и пересчет

Процесс сборки производных датасетов (`derive_symbol`) полностью идемпотентен:

- В файле `_derived_manifest.json` фиксируется отпечаток исходного файла событий (`name`, `size`, `version: DERIVE_VERSION`) и список созданных файлов.
- При повторном запуске день получает статус `skipped`, если файл событий не изменился и все сгенерированные файлы присутствуют на диске.
- **Условия автоматического пересчета (`processed`):**
  1. Изменился размер или контрольные свойства файла событий `events/.../<date>.parquet`.
  2. Передан флаг принудительной пересборки `force=True`.
  3. Пропал хотя бы один из ранее созданных parquet-файлов на диске.
  4. Повышена версия логики `DERIVE_VERSION` в [src/derived/runner.py](file:///Users/kyle/main/py_files/backtest_strat/src/derived/runner.py).
- Все операции с файлами защищены межпроцессным файловым замком `.derived.lock`.

### Сборка баров только из сделок (`derive_trades`)
Если L2-события за день отсутствуют, но имеются нормализованные файлы сделок за день $D$ и $D+1$ (покрывающие полные сутки UTC):
- Модуль [`src/derived/trade_bars.py`](file:///Users/kyle/main/py_files/backtest_strat/src/derived/trade_bars.py) автоматически агрегирует `bars_1s` и `bars_1m` напрямую из сделок.
- В манифесте фиксируется ключ `derive_trades: <day>`.
- Слой `l1` не создается, а поля `mid_close` и `spread_close` в барах остаются `null`.
- Дни с полными L2-событиями всегда имеют приоритет над сделками.

## 6. Примеры чтения данных

Для чтения данных используйте высокоуровневые функции из [src/storage/reader.py](file:///Users/kyle/main/py_files/backtest_strat/src/storage/reader.py):

### Чтение секундных баров за диапазон дат

```python
from datetime import date
from src.storage.reader import load_derived

table = load_derived(
    kind="bars_1s",
    symbol="BTC-USDT",
    start=date(2024, 1, 1),
    end=date(2024, 1, 7),
    columns=["ts", "open", "high", "low", "close", "volume", "vwap", "imbalance"],
)
df = table.to_pandas()
print(df.head())
```

### Чтение L1

```python
from datetime import date
from src.storage.reader import load_derived

l1_table = load_derived(
    kind="l1",
    symbol="BTC-USDT",
    start=date(2024, 1, 1),
    end=date(2024, 1, 1),
)
print(f"Всего тиков L1: {l1_table.num_rows:,}")
```

### Проверка списка файлов

```python
from datetime import date
from src.storage.reader import derived_files

files = derived_files("bars_1m", "BTC-USDT", date(2024, 1, 1), date(2024, 1, 31))
for path in files:
    print(path)
```

## 7. Запуск сборки

### Через CLI (`src.cli`)

Запуск только сборки производных датасетов:
```bash
python -m src.cli --exchange okx --symbol BTC-USDT --stage derive --start 2024-01-01 --end 2024-01-10
```

Полный пайплайн (скачивание $\to$ нормализация $\to$ валидация $\to$ производные датасеты):
```bash
python -m src.cli --exchange okx --symbol BTC-USDT --stage all --mode backfill --start 2024-01-01 --end 2024-01-10
```

Принудительная пересборка:
```bash
python -m src.cli --exchange okx --symbol BTC-USDT --stage derive --force
```

### Через Web UI

1. Перейдите на вкладку **«Запуск пайплайна»**.
2. В выпадающем списке «Стадия пайплайна» выберите **«Только производные датасеты»** (или «Скачать + нормализовать + проверить + производные»).
3. Нажмите кнопку **«Запустить пайплайн»**. Прогресс и результаты отобразятся в реальном времени.
