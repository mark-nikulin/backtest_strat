# Документация Web UI и HTTP API

Система включает в себя бэкенд на **FastAPI** с пулом фоновых задач в SQLite и интерактивный дашборд на **Streamlit** для мониторинга и запуска задач.

---

## 1. Быстрый запуск

Для работы требуются два процесса (API и Dashboard):

### Шаг 1: Запуск API-сервера
```bash
.venv/bin/uvicorn backtest_strat.api.app:app --host 0.0.0.0 --port 8000
```

### Шаг 2: Запуск веб-дашборда
```bash
.venv/bin/streamlit run backtest_strat/ui/dashboard.py --server.port 8501
```

После старта дашборд доступен в браузере по адресу: [http://localhost:8501](http://localhost:8501).

---

## 2. Архитектура: почему SQLite + ThreadPool, а не Celery/Redis

1. **Однопользовательский сценарий:** Пайплайн запускается квант-исследователем локально или на выделенном сервере сбора данных.
2. **Нулевая внешняя инфраструктура:** Celery требует внешнего брокера сообщений (Redis или RabbitMQ), отдельного процесса воркера, celery-beat и мониторинга (Flower). SQLite встроен прямо в стандартную библиотеку Python и не требует сторонних сервисов и демонов.
3. **Сохранение состояния и перезапуск:** Задачи хранятся в файле SQLite (`data/jobs.sqlite`). При перезапуске API-сервера метод `fail_interrupted()` корректно помечает незавершенные задачи статусом `failed`, исключая «зависшие» процессы.
4. **Легковесный мониторинг прогресса:** Прогресс задач (0.0 .. 1.0) сбрасывается в SQLite с шагом не менее 0.5%, снижая нагрузку на ввод-вывод.

## 3. Переменные окружения (Environment Variables)

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `PIPELINE_API_URL` | `http://127.0.0.1:8000` | URL бэкенда для Streamlit UI. |
| `PIPELINE_RAW_DIR` | `data/raw` | Путь к директории сырых архивов. |
| `PIPELINE_PROCESSED_DIR` | `data/processed` | Путь к директории обработанных Parquet-файлов. |
| `PIPELINE_JOBS_DB` | `data/jobs.sqlite` | Путь к файлу базы данных SQLite с реестром задач. |

## 4. Спецификация HTTP API

### Общие эндпоинты
| Метод | Путь | Описание | Статус |
| :--- | :--- | :--- | :--- |
| `GET` | `/health` | Проверка жизнеспособности сервера. | `200` |
| `GET` | `/meta` | Список доступных бирж, типов данных и каталогов. | `200` |
| `GET` | `/exchanges/{exchange}/symbols` | Список торгуемых тикеров с биржи (параметр `inst_type=SPOT\|SWAP\|FUTURES`). | `200`, `422`, `502` |
| `GET` | `/coverage/{exchange}/{symbol}` | Календарная матрица доступности сырых файлов и событий по дням. | `200`, `404` |
| `GET` | `/validation/{exchange}/{symbol}` | Сохраненные отчеты валидации по дням, список missing_days и невалидированных файлов. | `200` |

### Управление фоновыми задачами
| Метод | Путь | Описание | Статус |
| :--- | :--- | :--- | :--- |
| `POST` | `/jobs` | Создание и запуск новой задачи (`stage=all\|ingest\|normalize\|validate\|derive`). | `202`, `422` |
| `GET` | `/jobs` | Список последних задач (параметр `limit=50`). | `200` |
| `GET` | `/jobs/{id}` | Детальный статус, процент прогресса и итоговый отчет по задаче. | `200`, `404` |

### Логи и расписание
| Метод | Путь | Описание | Статус |
| :--- | :--- | :--- | :--- |
| `GET` | `/logs` | Поиск и фильтрация логов пайплайна (`days`, `level`, `source`, `q`, `limit`). | `200` |
| `GET` | `/schedule` | Текущий статус ночного расписания (`enabled`, `cron_installed`, `will_run`). | `200` |
| `PATCH`| `/schedule` | Изменение параметров расписания в `config/schedule.json`. | `200`, `422` |

## 5. Вкладки Streamlit Dashboard

1. **Задачи:** Интерактивный список активных и завершенных фоновых задач с автообновлением фрагмента каждые 2 секунды, прогресс-баром и выводом сводного отчета `summary` / `failed`.
2. **Покрытие данных:** Визуальная таблица наличия сырых архивов `trades`, `orderbook` и готовых Parquet-файлов `events` по календарным датам.
3. **Качество данных:** Визуальный дашборд контроля качества (`validate`): счетчики OK / WARN / FAIL, число пропущенных дней, подробные карточки по дням со списком проверок и примерами аномалий.
4. **Расписание:** Настройка времени ночного запуска, перечня инструментов и глубины перепроверки (`lookback_days`).
5. **Логи:** Поиск по системным логам с фильтрацией по источникам (`cli`, `cron`, `api`, `ui`) и уровням важности.
