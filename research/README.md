# research/

Исследования торговых идей на инструментах проекта. Принцип: **один набор инструментов на все идеи** — данные, проверки качества,
движок, статистика берутся из `src/`; в папке эксперимента лежит только специфика идеи.

| Папка | Что |
|---|---|
| [template/](template/) | Шаблон ноутбука для новой идеи (предрегистрация → качество → признаки → оценка → издержки → устойчивость → решение) |
| [exp01_seasonal_weather_liquidity/](exp01_seasonal_weather_liquidity/) | Сезонность × погода × ликвидность на 16 активах OKX: результат, журнал проблем, разбор |

## Новый эксперимент

1. `cp -r research/template research/exp02_<название>` и заполнить раздел 1 ноутбука (гипотеза, критерии отказа) **до** расчетов.
2. Данные: `python -m src.cli ... --data-type trades --stage all` (достаточно сделок для идей на барах).
3. Перед интерпретацией — откалибровать тест на синтетике с известной истиной (`exp01/calibrate.py` как образец).
4. Каждая проблема — в `PROBLEMS.md` рядом: что → почему → как устранили.
5. Следить за ходом: `streamlit run src/ui/monitor.py`.

## Чек-лист честности (из опыта exp01)

- Параметры заморожены до прогона; изменение после — запись «пост-фактум».
- Валовый результат отдельно от чистого.
- Поправка на множественные сравнения по всем проверенным активам/вариантам (FDR).
- Тест проверен на данных без закономерности (ложные срабатывания ≈ номинал) и с закономерностью (мощность).
- Две независимые оценки одной величины (движок и векторная) — расхождение объяснено.
- Устойчивость по подпериодам; эффект в одном месяце — не эффект.
- Отрицательный результат формулируется с границей: «эффекты не меньше X при мощности Y».
