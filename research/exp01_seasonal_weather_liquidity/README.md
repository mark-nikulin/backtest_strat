# exp01 — сезонный паттерн + погодный фактор + эффект ликвидности

Цель эксперимента двойная:
1. **Проверить механику**: можно ли на инструментах проекта (данные → качество → признаки → движок → статистика)
   честно проверить идею «от гипотезы до решения» без самописных костылей под идею.
2. **Найти активы**, на которых эта комбинация работает (если работает вообще).

Все найденные по пути проблемы и их решения — в [PROBLEMS.md](PROBLEMS.md). Шаблон для следующих идей — [../template/](../template/).

## Гипотеза

| | |
|---|---|
| **Сезонность** | Доходность в данный час суток (UTC) повторяет среднюю доходность того же часа за предыдущие 28 дней. Сигнал: знак среднего при \|t\| ≥ 1. |
| **Погода** | Эффект сезонного сигнала зависит от погодного режима: композитная z-аномалия суточной температуры (Нью-Йорк, Лондон, Токио, Гонконг) за вчерашние сутки. Фильтр M1: торговать только при \|z\| ≥ 1. |
| **Ликвидность** | Эффект сильнее при тонком рынке: объем за предыдущие 24ч / средний суточный объем за 30 дней < 1. Фильтр M2. |

**Механизм** (слабый, поэтому и нужна строгая проверка): сезонность — циклы активности участников по часовым поясам;
погода — опосредованный канал через энергозатраты/настроение/майнинг, априори малоправдоподобный;
ликвидность — на тонком рынке потоки двигают цену сильнее и возврат медленнее. Погодный фактор — самое сомнительное звено,
и именно его поведение на 16 активах — главный тест механики (нужна защита от ложных находок).

## Варианты (четыре, фиксированы)

| | Правило |
|---|---|
| M0 | только сезонный сигнал |
| M1 | сезонный сигнал × погодный фильтр |
| M2 | сезонный сигнал × фильтр ликвидности |
| M3 | сезонный сигнал × оба фильтра |

## Данные и период

- 16 спотовых пар OKX к USDT (от BTC до ATOM — разная ликвидность), только сделки (`--data-type trades`).
- 2024-01-01 … 2024-06-29 (UTC), 1-минутные бары → часовые. Подпериоды для устойчивости: Q1 и Q2.
- Погода: Open-Meteo Archive (ERA5), задержка 1 день.
- Издержки: taker 10 б.п. (основной сценарий) и 2 б.п. (низкий тир), полуспред — по снимку биржи.

## Критерии (зафиксированы до полного прогона)

Актив признаётся **подходящим** для компонента, если одновременно:

| Компонент | Критерий |
|---|---|
| Сезонность | валовый edge > 0 **и** q (BH по 16 активам) < 0.10 **и** тот же знак валового результата в Q1 и Q2 |
| Погода | selectivity > 0 **и** q < 0.10 **и** коэффициент взаимодействия в регрессии с t ≥ 2 того же знака |
| Ликвидность | то же для фильтра M2 |
| Торгуемость | чистый PnL > 0 и daily-t ≥ 2 при taker 10 б.п. **и** при 2 б.п. |

С 16 активами × 3 теста = 48 проверок: при 5% ложных срабатываний ожидаем ~2.4 «находки» **случайно**. Поэтому — FDR-поправка,
а не сырые p-value.

## Оговорка о «чистоте»

Результаты BTC-USDT были просмотрены при отладке конвейера до полного прогона по всем активам.
Параметры при этом **не подбирались под результат**; единственное изменение конфигурации — нижняя граница полуспреда
(0.5 → 0.005 б.п.), вызванная сверкой с реальным L1 (PROBLEMS.md, P5), а не качеством PnL.
