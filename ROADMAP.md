# Roadmap: от пайплайна данных к бэктестеру

Статусы: `[ ]` не начато · `[~]` в работе · `[x]` готово

## Готово: пайплайн данных
- [x] Ingestion: OKX trades + L2 400lv, retries, атомарная запись, идемпотентность, backfill/daily
- [x] Normalization: единая схема событий (ns), детерминированная сортировка, Parquet year=/month=, events за UTC-день
- [x] Интерфейсы: CLI, FastAPI + фоновые задачи (SQLite), Streamlit-дашборд
- [x] Ops: планировщик (выключен по умолчанию), централизованные логи, вкладки Logs/Расписание

## 1. Восстановление стакана + контроль качества данных
- [ ] `OrderBook`: snapshot = сброс, применение пачкой по `msg_id`, `size == 0` = удаление уровня
- [ ] Сверка восстановленной книги с минутными снапшотами OKX (1440 контрольных точек/день)
- [ ] Стадия `validate` после нормализации: crossed book, дыры по времени, сделка вне спреда, скачки цены с возвратом, пропущенные дни
- [ ] Результаты проверок в manifest + отображение в дашборде

## 2. Производные датасеты (крон)
- [ ] L1 / top-of-book: best bid/ask + объемы на каждое изменение
- [ ] Бары 1s / 1m: OHLCV, VWAP, buy/sell imbalance
- [ ] Срезы L10 каждые N мс
- [ ] (опц.) ClickHouse для L1 и баров

## 3. Движок бэктеста (одна библиотека на все альфы)
- [ ] Интерфейс стратегии: `on_book`, `on_trade`, `on_timer`
- [ ] Симулятор биржи: латентность (данные и ордера), комиссии maker/taker, частичные исполнения, позиция в очереди, проскальзывание market-ордеров
- [ ] Портфель и PnL: mark-to-market, отчет (Sharpe, просадка, оборот, fill ratio, maker/taker PnL)
- [ ] Учесть отсутствие локального времени получения у OKX: латентность моделируется обязательно

## 4. Единый загрузчик
- [ ] `load(exchange, symbol, kind, freq, start, end, frame="polars"|"pandas")` на `polars.scan_parquet`

## 5. Производительность (когда начнет тормозить)
- [ ] `orjson` + ProcessPool по файлам
- [ ] При необходимости: парсер стакана на Rust

## 6. Расширение данных
- [ ] SWAP и другие тикеры
- [ ] Funding rates (резолвер OKX, `module: 3`)
- [ ] Real-time запись через websocket (5000lv, ликвидации)

## 7. Исследования
- [ ] Шаблон ноутбука: стратегия + датасет → отчет

Порядок: 1 → 2 → 3 → 4, пункт 5 — по мере надобности.
