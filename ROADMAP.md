# Roadmap: от пайплайна данных к бэктестеру

Статусы: `[ ]` не начато · `[~]` в работе · `[x]` готово

## Готово: пайплайн данных
- [x] Ingestion: OKX trades + L2 400lv, retries, атомарная запись, идемпотентность, backfill/daily
- [x] Normalization: единая схема событий (ns), детерминированная сортировка, Parquet year=/month=, events за UTC-день
- [x] Интерфейсы: CLI, FastAPI + фоновые задачи (SQLite), Streamlit-дашборд
- [x] Ops: планировщик (выключен по умолчанию), централизованные логи, вкладки Logs/Расписание

## 1. Восстановление стакана + контроль качества данных
- [x] `ReplayBook` (ядро из hft_sim): snapshot = сброс, применение пачкой по `msg_id`, `size == 0` = удаление уровня
- [~] Сверка восстановленной книги с минутными снапшотами OKX — разовая проверка сделана, нужна стадия `validate`
  - Находка (BTC-USDT, 2024-01-01): диффы OKX неполные. Перед снапшотом лучшая цена совпадает в 99.5%,
    объем на лучшем уровне расходится в 10.9% (медиана 26%); top-5 целиком совпадает ~63%.
    Ошибка ограничена минутой (снапшот сбрасывает книгу). Следствие: taker-исполнение достоверно,
    queue-ahead для maker-ордеров шумный.
- [ ] Стадия `validate` после нормализации: crossed book, дыры по времени, сделка вне спреда, скачки цены с возвратом, пропущенные дни
- [ ] Результаты проверок в manifest + отображение в дашборде

## 3. Движок бэктеста (одна библиотека на все альфы) — `src/backtest/`

- [x] Симулятор биржи (ядро из hft_sim + доработки): feed/order latency, maker/taker, GTC/IOC/FOK/PostOnly, частичные исполнения,
      queue-ahead с ограничением по уровню, trade-through, учет съеденной ликвидности, задержка отмен
- [x] Портфель и PnL: средняя цена, realized/unrealized, кривая equity, отчет (Sharpe, просадка, оборот, maker share, order fill ratio)
